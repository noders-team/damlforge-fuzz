How the fuzzer changes the seed contracts

Every input is a fresh copy of one original seed with 1 to 4 small changes. The fuzzer never changes a changed copy again. A longer run only makes more inputs. Step through real inputs below, and see what happens when you add a new contract.

The one rule: every input starts again from a seed

What the fuzzer does

The first 16 inputs of random seed 1, sorted by the seed each one starts from. Each input is a copy of the original seed with its own changes.

What it does not do

iou.vy → change it → change that again → and again

The seeds on disk never change, and no input is made from an earlier input. So input 5000 is no more "changed" than input 5. A crash at input 5000 is 1 to 4 changes away from a seed, so it is easy to read.

Run it yourself

Run these commands from the damlforge-fuzz folder, in the virtual environment that has DamlForge and the fuzzer. The first command gives the counts. The second command prints each input: the changes, the lines that changed, and the result. Both use the same inputs.

$ damlforge-fuzz run contracts/iou --count 6 --random-seed 1
random seed 1, 1 seed, 6 inputs
random seed 1: 6 inputs, 1 OK, 4 rejected, 1 crash, 0 skipped

$ python scripts/show_inputs.py contracts/iou --count 6 --random-seed 1

In change 2: name on line 3, the line number is the line in the text before that change. The @@ -33 +33 @@ lines compare the input with the original seed. Use other folders, such as contracts/ballot, or no folder for all seeds. Change --random-seed to see other inputs.

What happens when you add a new contract

To test this, a new seed contracts/vault/vault.vy was added next to the four seeds, in a copy of the project. It has one template, Vault, with the choices Deposit and Withdraw. forge compiles it OK. You add a seed like this:

  1. Make the folder contracts/vault/ and copy daml.yaml from contracts/iou/. Change its name to damlforge-fuzz-vault.
  2. Put vault.vy in the folder and run the two seed checks in the guide.
  3. Run the fuzzer. Without a folder argument, the run uses every folder in contracts/, so it finds the new seed. You change nothing else.

From then on, three things change in each run:

  • About one input in five starts from the new seed. Each input picks one of the seeds with the same chance.
  • The donor_line rule can borrow lines from vault.vy and insert them into copies of the other seeds.
  • The same random seed gives a different list of inputs. Most inputs stay the same, but not all.
